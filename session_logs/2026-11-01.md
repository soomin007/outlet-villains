# 2026-11-01 세션 로그

## 요약
설정창을 화면 크기에 맞춰 키우고, 걸음 수 아래 버튼 간격을 띄웠다. Codex가 그린 네 묶음 34장(주인공 표정 12, 빌런 고유색 7, 큼직한 탁자 물건 7, 메인 화면 달리는 로봇 4와 흐르는 카페 1과 이스터에그 3)을 검토해 게임에 붙였다.
오늘 작업은 여기서 마친다.

## 주요 변경
- `index.html` 설정창: 글자 크기 하나(--panel-font, 1366 x 768에서 약 19px, 1920 x 1080에서 약 23px, 휴대폰 16px)만 화면으로 정하고 폭과 칸 높이를 모두 em으로 비례시켰다.
  켜고 끄는 줄 아래 버튼은 1em 띄운다. 탭 높이는 화면에 들어가는 만큼까지만 맞춰서 긴 조작 탭만 창 안에서 스크롤된다. 400px 이하에서는 안쪽 여백을 줄이고 글자 크게를 1.125배까지만 키운다. "방향 버튼"은 "화면 방향 버튼"으로 이름을 바꿨다.
- `index.html` 주인공: 얼굴 화면 표정(밀 때 힘줌, 부딪히면 어지러움, 판을 깨면 웃음), 6초 동안 가만히 두면 두리번거리고 15초가 지나면 졸린 눈, 로봇을 누르거나 Space를 누르면 삐빅 소리와 함께 뛰며 웃는다. 조작법 표에 로봇 누르기를 더했다.
- `index.html` 탁자 물건: 노트북 치는 손님(seated-1) 앞에는 그 손님이 바라보는 방향의 노트북, 다른 손님 앞에는 컵, 나머지는 다섯 칸에 한 칸 꼴로 꽃병이나 케이크.
- `index.html` 메인 화면: 로봇 자리 뒤로 옆에서 본 카페가 36초에 한 바퀴 오른쪽에서 왼쪽으로 흐르고, 로봇은 네 장면을 0.11초마다 바꾸며 제자리에서 달린다. 만난 빌런과 충전 독이 이스터에그로 지나간다. 움직임 줄이기를 켜면 멈춘다.
- Codex 그림 34장과 `assets/manifest.js`, `assets/generation.json`, Codex 세션 로그.

## 결정 사항
- 설정창 글자는 Xbox 접근성 지침(XAG 101)의 1080p PC 본문 18px 기준을 따랐다. 해상도 설정은 넣지 않았다. 장면은 창 크기에 맞춰 저절로 커지고 줄며(fitScene), 그림은 1920 x 1080으로 그려 브라우저가 화면 해상도에 맞게 그리므로 따로 고를 것이 없다. 창 크기는 전체 화면(F)으로 바꾼다.
- 기본값은 대부분 지금까지의 동작을 그대로 두었다(목표 짚기 켜짐, 화면 흔들림 켜짐, 방향 버튼 자동, 음악 60과 효과음 50). 판 안에서는 글을 줄인다는 원칙으로 걸음 수와 격자는 꺼짐이다.
  창을 떠나면 소리 끄기(켜짐)와 키 반복 간격 150ms(이동 연출 130ms보다 조금 길게)는 Claude Code가 정한 값이라 사용자가 바꿀 수 있다.
- 메인 화면 카페 띠는 로봇 자리를 가운데로 화면 폭의 3배만큼 깔아서, 로봇이 왼쪽에 있든(PC) 가운데 있든(휴대폰) 화면 양 끝까지 덮는다.
- 표정은 상태를 새 방향으로 바꾼 뒤에 정한다. 먼저 정했더니 부딪히거나 밀며 방향이 바뀔 때 예전 방향의 표정 그림이 그려졌다(시험에서 찾아 고침).

## 세션 2 (1-4 지적, 레벨 점 키보드, 의뢰 방식 점검)

### 요약
사용자가 1-4의 구석, 컵, 빌런 탁자의 꽃병, 손님 키, 옆으로 앉은 손님의 발과 레벨 이동 Tab, 메인 화면 구성, 로봇 표정, 그림 의뢰 방식을 지적했다.
장면을 확대하고 그림 크기를 재서 원인을 찾았고, 동의한 버그(컵, 꽃병, 손님 키, 발, 레벨 점 키보드)만 고쳤다. 벽, 음료, 메인 화면, 로봇 표정, 의뢰 방식은 의견을 낸 채 사용자 결정을 기다린다.

### 주요 변경
- `index.html` 실내: 머그를 든 기존 손님 셋과 폰 보는 손님 앞 탁자는 비운다(두 잔짜리 table-cups를 쓰지 않음). 빌런 자리(V)에 붙은 탁자에는 꾸밈 물건을 놓지 않는다.
  새 손님 둘(seated-1, seated-2)은 250 / 212배로 키운다(GUEST_SCALE). 옆으로 앉은 손님은 상판과 겹치는 부분에서 그림 높이 64% 아래를 잘라 낸다(tuckLegs, LAP_LINE).
- `index.html` 레벨 점: 지금 레벨 점 하나만 Tab을 받고 ←→(A D)로 점 사이를 옮긴다(moveDotFocus, DOT_STEPS). 점에서 ↑↓를 누르면 초점을 점 막대 자리에서 풀어,
  로봇이 움직이고 다음 Tab은 다시 지금 레벨 점으로 온다. 조작법 표의 레벨 고르기 문구를 고쳤다.
- `known-issues.md` 24번(그림을 한 장씩만 검수), 25번(메인 화면 목업 건너뜀). `docs/art-rules.md` 인물 절에 손님 키 250px, 무릎 아래 64% 자르기, 손에 든 물건과 탁자 물건 규칙.
- Claude Code 메모리에 "사용자 의견은 검토해서 내 의견을 먼저 말한 뒤 반영한다"를 남겼다.

### 결정 사항
- 손님 키는 기존 손님(캔버스의 87%)에 맞췄다. 실제 앉은키로는 74%가 더 가깝지만, 판의 손님 대부분과 로봇의 1.2배 크기가 기존 손님에 맞춰져 있다.
- 발은 손님을 다시 그리기 전까지 코드로 가린다. 상판 위의 손과 머그는 보이고 무릎 아래만 숨는 것이 실제 겹침 순서다. 다섯 사람 모두 손이 그림 높이 50~63%, 정강이와 발이 64% 아래라 숫자 하나로 된다.
- 레벨 점은 WAI-ARIA 도구 막대의 roving tabindex 방식을 따랐다. 설정창 탭을 ←→로 바꾸는 방식과 같다.
- 확인한 것: Tab 한 번에 1-4 점, →세 번에 2-2, Enter로 2-2 시작, 점에서 ↓는 로봇 이동과 초점 풀기. 조작법 문구는 320, 360, 390, 1440 폭에서 두 묶음 사이에서만 줄이 바뀌고 가로 넘침이 없다. 콘솔 오류 없음.

### 미해결 / 다음 할 일

## 세션 3 (결정과 규칙 정리)

앞으로 설계 회의는 effort max, 실제 작업은 effort high로 하므로, 이번 세션은 코드를 고치지 않고 결정과 규칙을 문서에 정리하는 데만 썼다.

### 결정 사항
- 로고는 사용자 제안대로 배터리 받침을 쓴다. 빨간 글씨는 회색 배경과의 명암비가 1.4~1.9 대 1이고, 검은 바탕 위 흰 글씨는 21 대 1이다.
  Claude Code가 보탠 것은 두 가지다. 받침이 배터리라 로고 끝 배터리 느낌표와 겹치므로 목업에서 두 가지를 비교하고, 받침은 CSS로 먼저 그린다.
- 손님은 여자 넷, 남자 넷이고 20대 넷, 10대 후반 하나, 30~40대 둘, 60대 하나다. 자세마다 남녀 한 명씩이고, 음료는 다섯 종류를 두 번까지 쓴다. 시험은 2번(여, 20대, 노트북)과 8번(남, 60대, 컵)으로 받는다.
- 문서의 역할을 나눴다. 매번 지킬 것은 CLAUDE.md, 그림 결정과 의뢰서 양식과 받은 그림 검사는 art-rules.md, 게임과 화면 결정은 concept.md, 할 순서는 세션 로그의 다음 할 일이다.

- 사용자가 말한 "2번 선택지"는 10월 31일 새 기믹 후보의 2번(걸어 다니는 손님)이었다. Claude Code가 13판 범위 질문으로 잘못 짚었다.
- 걸어 다니는 손님은 필수 작업을 먼저 끝낸 뒤 남는 시간에 넣자고 권했다. 보류 이유는 토큰이 아니라 시간과 검증 부담이었고, 요금제가 바뀌어도 그대로다. 사용자 결정 대기.
- 사용자가 "필수 먼저, 걸어 다니는 손님은 남으면"에 동의했다. 수업 전까지 남은 작업은 effort max로 하고 ultracode는 쓰지 않는다(CLAUDE.md "매번 지킬 것" 머리에 적음).
- 사용자는 처음 하는 사람도 1장을 깨는 데 10분까지 걸리지 않는다고 봤다. Claude Code가 말한 "10분 동안 대부분 1장"은 근거가 최소 걸음 수(1장 64걸음)뿐이었다.
  그 말이 맞다면 수업에서 2장과 3장까지 보는 사람이 많으니, 13판 모두 필수라는 결정과도 맞는다. 처음부터 끝까지 해 보기에서 챕터마다 걸린 시간을 잰다.
