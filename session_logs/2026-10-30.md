# 2026-10-30 세션 로그

## 요약
옆벽 조작법 안내의 꼬물거림을 줄이고 오른쪽 정렬과 반투명으로 바꿨다. 배경 그림의 채도와 대비를 낮춰 움직일 수 있는 것이 앞으로 나오게 했다.
로봇 주인공 그림과 만화 프롤로그는 사용자 결정(로봇 생김새, 컷 구성)을 기다린다.

## 주요 변경
- `index.html`: 안내 글자 움직임을 0.3px, 1.2도 안쪽으로 줄이고 0.75초 주기로 바꿈, 오른쪽 정렬, 투명도 55%. 배경 그림에 saturate(0.6) contrast(0.78) brightness(1.08)

## 결정 사항
- 로봇 그림은 아직 만들지 않았다. 생김새는 사용자가 정하는 것이라(known-issues 11번) 후보를 시험 생성해 고르게 한다.
- 지금 프롤로그 글 카드는 로봇과 컷 구성이 정해지기 전까지의 임시였다. 만화 컷으로 바꾼다.

## 미해결 / 다음 할 일
- 로봇 후보 시험 그림을 Codex에 의뢰하고 사용자가 고른다
- 만화 프롤로그 컷 구성을 사용자가 확인하면 Codex에 의뢰한다(WebP, 미리 불러오기)
- 2장 레벨

## 세션 2 (Claude Code, 2장 다시 만들기와 3장)

### 요약
2장을 손님과 테이블로 좁힌 다섯 레벨(5, 13, 22, 27, 39걸음)로 다시 만들고, 두 챕터를 응용하는 3장 "합석" 세 레벨(24, 34, 48걸음)을 더했다. 새 그림 없이 촬영자(F) 규칙만 엔진에 더했다.

### 주요 변경
- `src/engine.js`: F(촬영자) 칸, 화각의 기준을 촬영자로, 쓰레기통이 촬영자 화각에 비치면 state.gone, 진동벨 자리가 있으면 진동벨로 이김, 해법 탐색을 앞 상태 번호 방식으로 바꿔 메모리 절약
- `src/layout.js`: 2장 레벨 다섯 개, 3장 챕터와 레벨 세 개(filmer 그림, maxWalk)
- `index.html`: 촬영자 그림, 촬영자가 떠나는 연출(filmerLeaves), 되돌리기 때 촬영자 되살리기(syncFilmer), 촬영 화면 창 얼굴
- `tools/verify.html`: 의자 쓰임(벽 또는 치우기), 퍼즐 기준(함정 또는 30걸음), maxWalk, 촬영자 칸
- `docs/concept.md`, `docs/level-design.md`: 2장과 3장 설명, 바꾼 검증 기준

### 결정 사항
- 3장은 새 빌런 그림이 필요 없도록 1장 빌런(목표)과 2장 촬영자(장애물)를 한 판에 합쳤다. 쓰레기통으로 촬영자를 먼저 보내는 두 단계 구조다.
- 3장 무작위 탐색은 물건이 많아 느려서(13초에 150개 남짓), 방 모양을 먼저 설계하고 물건 구역만 탐색했다. 손으로 놓은 배치는 진동벨이 갇히거나 주인공이 갇히는 실수가 두 번 있었다.
- 2장과 3장의 손님 배치는 자동 규칙 3판(테이블은 두 칸 이상 이어질 때만, 외딴 칸은 소품)으로 했다. 풀이는 배치 전후가 같다.
- 3-2의 의자 두 개와 3-3의 의자 하나는 풀이에 쓰이지 않아서 뺐다.

### 미해결 / 다음 할 일
- 사용자가 2장과 3장을 해 보고 난이도를 알려 준다
- 2, 3장의 자동 손님 배치가 어색한 곳이 있으면 손으로 고친다
- Codex 로봇 2차 시험과 충전 독 그림을 기다린다(폴더 감시 중)

## 세션 3 (Claude Code, 로봇 생김새와 충전 독)

### 요약
로봇 2차(원반과 집게팔 등)와 3차(팔 위치 세 가지) 시험 그림을 비교해 사용자가 3차 8번(원반 위 원통 몸통 양옆에 팔)을 골랐다. 충전 독을 게임에 넣었다.

### 주요 변경
- `index.html`: 콘센트 옆 벽 아래 충전 독, 독에서 나온 선과 바닥에 뽑힌 플러그(drawDockCord), 판 시작 때 그 플러그를 짚기(머리 위 말풍선 대신), 판을 깨면 독의 선이 콘센트에 꽂힘
- `CLAUDE.md`, `docs/concept.md`: 로봇 생김새 결정
- Codex 파일 커밋: 로봇 시험 그림 4~9번, `assets/a|b/dock.png`, manifest, generation.json, Codex 세션 로그

### 결정 사항
- 팔은 몸 색과 다른 진한 회색이라야 게임 속 크기(높이 약 80px)에서 보인다. 원반 몸에서 팔이 솟는 구조는 어색하다는 사용자 지적으로 몸통에 팔을 붙였다.
- 독의 위치는 콘센트 오른쪽 한 칸(판 끝이면 왼쪽)이다. 판 지도에는 넣지 않고 벽 아래에 그림만 놓는다.

### 미해결 / 다음 할 일
- Codex에 로봇 네 방향 그림(player-up/down/left/right 교체)과 프롤로그 만화 컷을 의뢰한다
- 프롤로그 컷이 오면 글 카드를 만화 컷으로 바꾸고 미리 불러온다

## 세션 4 (Claude Code, 로봇 주인공과 만화 프롤로그)

### 요약
Codex의 로봇 네 방향 그림으로 주인공을 바꿨고, 프롤로그를 글 카드에서 글 없는 만화 다섯 컷으로 바꿨다. 레벨을 시작할 때 그림들이 왼쪽 위에서 미끄러져 들어오던 버그를 고쳤다.

### 주요 변경
- `index.html`: 프롤로그를 story-1 ~ story-5 만화 컷으로(그림이 없으면 짧은 글 카드), 만화 카드 배치, 처음 그릴 때 움직임 효과 끄기(.instant)
- `known-issues.md`: 20번(그림이 미끄러져 들어옴)
- Codex 파일 커밋: 로봇 player 네 방향 두 테마

### 결정 사항
- 만화 컷은 WebP 1280 x 720, 한 장 44~105KB(열 장 합계 약 670KB)라 테마 그림과 함께 미리 받는다.
- Codex 세션 로그가 "커밋 대기"를 한 작업에 두 번 적어서, 감시가 의뢰 두 개 가운데 하나만 끝났을 때 울렸다. 감시 조건은 결과 파일이 생겼는지로 거는 것이 낫다.

### 미해결 / 다음 할 일
- Codex가 만화 컷의 생성 기록과 세션 로그를 남기면 컷 열 장과 manifest를 커밋한다

## 세션 5 (Claude Code, 제목과 메인 화면)

### 요약
처음 방향을 바꿀 때의 그림 지연을 받는 순서로 줄이고, 제목을 "충전이 필요해!"로 바꿨다. 메인 화면(이어하기, 처음부터, 설정)과 진행 저장을 넣었다.

### 주요 변경
- `index.html`: 그림을 주인공과 물건, 지금 배경, 나머지 순서로 받기. 메인 화면(만화 1번 컷 배경, 로봇, 글자 로고 대체, 버튼), 깬 레벨과 이어 할 레벨 저장, 엔딩 뒤 메인 화면으로, 페이지 제목
- `README.md`, `CLAUDE.md`: 제목 바꾸기

### 결정 사항
- 로딩 화면은 두지 않는다. 그림은 메인 화면과 프롤로그가 떠 있는 동안 받는다(사용자 결정). 메인 화면의 첫 입력이 소리를 켜는 계기가 된다.
- 로고(title-logo)와 메인 화면 로봇(title-robot)은 Codex 그림이 오기 전까지 글자 로고와 주인공 앞모습으로 대신한다. 글자 로고는 둘째 줄을 한 글자만큼 밀어 '필'이 '전' 아래에 온다.
- "처음부터"는 프롤로그부터 다시 보여 준다. 깬 기록이 없으면 "시작하기" 버튼 하나만 크게 보인다.

### 미해결 / 다음 할 일
- Codex에 제목 로고와 메인 화면 로봇 그림을 의뢰한다
- 큰 PNG(배경, 일러스트)를 WebP로 바꾸는 것을 검토한다
