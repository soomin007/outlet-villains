# 그림 규칙

그림에 관한 결정은 여러 날의 세션 로그에 흩어져 있었다. 새 세션은 가장 최근 로그만 읽어서, 이미 정한 결정을 어기는 의뢰를 다시 썼다(known-issues 23번).
그래서 그림에 관한 결정은 이 문서 한 곳에 모은다. Claude Code는 Codex 의뢰를 쓰기 전에 이 문서를 읽고, 의뢰 끝에 "대조한 규칙" 줄로 지킨 항목을 적는다.
새 결정이 생기면 세션 로그와 함께 이 문서에도 적는다. 출처는 괄호 안의 날짜와 문서다.

## 인물

- 인물의 성별, 나이, 머리 모양, 옷 같은 생김새는 사용자가 정한 것만 적는다. 빈 곳은 Claude Code가 채우지 않고, 후보 두세 개를 시험 생성해 사용자가 고르게 한다(known-issues 11번, 23번).
- 손님과 빌런은 성별이 드러나지 않게 그린다. 지금까지의 손님 의뢰는 모두 이 문장을 넣었다(2026-10-29 Codex 로그, concept.md).
- 레퍼런스 속 인물의 성별, 체형, 얼굴이 결과에 묻어나지 않게 막는다(known-issues 11번).
- 이미 있는 인물 세트를 새 그림으로 통째로 바꾸지 않는다. 새 인물은 기존 인물과 섞어 쓰고, 바꾸려면 사용자에게 먼저 묻는다(2026-10-31, known-issues 23번).
- 같은 사람이 줄지어 앉으면 복제 인간처럼 보여서, 손님은 여러 사람을 칸마다 번갈아 쓴다(2026-10-29).
- 앉은 사람 그림은 의자와 함께 그리고, 의자 다리가 캔버스 아래에 닿는다. 서 있는 사람의 "발바닥을 캔버스 아래에" 규칙을 앉은 사람에게 그대로 쓰면 쪼그려 앉은 모습이 된다(2026-10-29).
- 테이블을 보고 앉은 손님은 게임이 테이블 쪽으로 칸의 35%만큼 당겨 앉힌다. 그래서 손님의 손은 테이블 가장자리 높이에 와야 하고, 허공에 들려 있으면 안 된다(2026-10-31).

## 주인공 로봇

- 생김새는 3차 시험 8번이다(2026-10-30 사용자 결정, CLAUDE.md). 바닥 원반 위 낮은 원통 몸통, 목과 얼굴 화면, 몸통 양옆에서 앞으로 뻗는 팔이다.
- 팔은 몸 색과 다른 진한 회색이라야 게임 크기(높이 약 80px)에서 보인다(2026-10-30).
- 로봇 몸에 코드나 플러그를 달지 않는다. 로봇은 충전 독에 올라앉아 충전한다(CLAUDE.md).
- 얼굴 화면 표정을 쓴다(2026-10-31 사용자 결정). 기본, 밀 때 힘줌, 부딪혔을 때 어지러움, 판을 깼을 때와 눌렀을 때 웃음, 가만히 둘 때 졸림이다. 위(뒷모습)는 얼굴이 보이지 않는다.
- 메인 화면의 로봇은 오른쪽을 보고 팔을 앞으로 뻗은 채 허겁지겁 제자리에서 달려나가는 옆모습이고, 뒤로 카페가 오른쪽에서 왼쪽으로 끝없이 흐른다(2026-10-31 사용자).
  흐르는 카페에는 지나간 빌런들과 충전 독, 콘센트가 이스터에그로 지나간다. 메인 화면만 옆에서 본 시점이고 게임 판은 위에서 비스듬히 본 시점이다.

## 색

- 그림체는 흑백(A) 한 벌만 쓴다(2026-10-31 사용자 결정). 카툰(B)은 A 그림을 참고로 그려 색만 바꾼 것처럼 보였고, 모든 그림을 두 벌 그리는 비용이 컸다. 새 그림은 A만 그린다.
- 배경, 손님, 가구는 흑백과 회색, 주인공은 빨강(#c8302a 근처) 하나, 밀 수 있는 물건은 초록(#2f7a54 근처) 하나다(2026-10-29).
- 빌런은 흑백 속에서도 한 사람에 고유색 하나를 쓴다(2026-10-31 사용자 결정). 잠든 카공족은 보라(#7b4fb0 근처), 공부 영상 촬영자는 파랑(#2f6db3 근처)이다.
  빨강(주인공), 초록(밀 수 있는 것), 노랑(화각)과 겹치지 않게 고른 색이고, 사용자가 바꿀 수 있다. 개성(대표 소품, 표정)은 후보를 시험 생성해 사용자가 고른다.
- 초록은 "밀 수 있다"는 뜻으로만 쓴다. 노랑은 카메라 화각 색이라 물건에 쓰지 않는다. 진동벨은 색 대신 모양, 크기(칸의 1.2배), 흔들림으로 구별한다(2026-10-29).

## 크기와 자리

- 크기는 실제 크기(cm), 그림 크기(px), 비율(%)을 함께 적고 말과 숫자를 대조한다(known-issues 7번).
- 칸 하나는 그림 파일에서 192px, 게임 그림 좌표에서 96px이고, 바닥으로는 약 60cm다. 서 있는 사람(170cm)이 칸 높이 1.5배(288px)라서 칸 높이 1배는 약 113cm다(2026-10-31).
- 눈에 보여야 하는 물건(음료, 쓰레기통, 의자, 진동벨)은 실제보다 크게 그린 지금 크기가 맞다. 배경 가구는 실제 크기와 개연성을 따른다(2026-10-31 사용자).
- 테이블 위에 놓는 물건은 실제 비율로 그리면 너무 작아 보여서 큼직하게 그린다(2026-10-31 사용자 제안).
- 테이블 위에는 방향이 있는 물건(노트북, 펼친 책)을 한 방향 그림으로 올리지 않는다. 손님이 네 방향에서 앉기 때문이다. 둥근 잔, 접시, 냅킨 통, 꽃병처럼 어느 쪽에서 봐도 같은 물건을 쓰거나, 방향이 있는 물건은 네 방향을 모두 그린다(2026-10-29, 2026-10-31).
- 화분과 소품은 게임이 바닥 기준선을 칸 높이의 18%만큼 올려 놓는다. 칸 아래 끝에 붙이면 칸 경계에 걸쳐 보였다(2026-10-31).
- 칸 높이를 넘는 물건(기둥)은 윗칸을 가린다. 로봇이 걷는 바닥을 가리는 자리에는 두지 않는다(2026-10-31).
- 배경 그림의 바닥 격자는 생성기가 정확히 지키지 못한다. 그림을 숫자에 맞추지 않고, 그림 속 격자를 재서 `assets/bg-grid.js`에 적는다(known-issues 14번).
- 이어 붙이는 조각(젖은 바닥, 테이블)은 96 x 96 귀퉁이마다 정하고, 의뢰 전에 이어 붙인 그림으로 이음매를 확인한다(known-issues 21번).

## 그리는 방식

- 그림체는 말 대신 레퍼런스 이미지로 맞추고, 레퍼런스는 한 장씩 그대로 넣는다. 원하는 것과 원하지 않는 것을 함께 적는다(known-issues 6번).
- 실제 사물은 나라와 종류까지 구체적으로 적는다. 적지 않으면 생성기가 미국식 기본값을 고른다(known-issues 6번).
- 투명 그림에는 흰 스티커 테두리와 바닥 그림자를 넣지 않는다. 게임이 상호작용할 수 있는 것에만 붙인다. 글자는 넣지 않는다(AGENTS.md).
- 로고와 일러스트는 정확한 정렬보다 전체 인상을 앞세운다고 적는다. "이 글자가 저 글자 아래"처럼 적으면 글자가 띄엄띄엄해졌다(2026-10-31).
- 맡길 때는 무엇을 바꾸는지와 함께 왜 바꾸는지, 화면에서 무엇이 읽혀야 하는지를 적는다(known-issues 10번).
- 큰 배경과 일러스트는 WebP로 줄인다. 작은 PNG(25~70KB)는 선이 또렷해야 해서 그대로 둔다(2026-10-31).
